# Граф зависимостей npm

Практическая работа №2 по конфигурационному управлению. Вариант 2, **этапы 1–5**.

Программа на Python анализирует прямые и транзитивные зависимости npm-пакетов.
Нужные данные берутся напрямую из публичного npm Registry через HTTP и JSON;
готовые npm-библиотеки и менеджер npm в самом анализаторе не используются.

## Требования

- Python 3.10+ (все библиотеки анализатора стандартные).
- Интернет для реальных пакетов.
- Graphviz (`dot`) для генерации и открытия PNG-графа в этапе 5.
- Node.js/npm **только** для независимого сравнения со штатными инструментами.

Windows: установить Graphviz можно командой `winget install graphviz`, затем
перезапустить VS Code/PowerShell и проверить `dot -V`.

## Запуск

Из корня проекта:

```powershell
.\run.bat
```

Основной запуск с тестовыми данными (картинка открывается автоматически):

```powershell
python src/main.py --stage 5 --package A --repo tests/fixtures/simple.json --test-mode --ascii-tree --show-order
```

Получить граф из npm Registry:

```powershell
python src/main.py --stage 5 --package is-even --repo https://registry.npmjs.org --ascii-tree --show-order
```

Параметры:

- `--package` — имя пакета (`A` в тестах, `is-even` в npm).
- `--repo` — путь к JSON-файлу тестового репозитория или URL npm Registry.
- `--test-mode` — читать JSON-граф вместо запросов в интернет.
- `--ascii-tree` — печатать дерево зависимостей.
- `--stage 1..5` — показать функциональность выбранного этапа (по умолчанию 5).
- `--show-order` — показать порядок зависимостей перед зависимыми (этапы 4–5).
- `--compare-npm` — сравнить прямые зависимости с `npm view` (этапы 4–5).
- `--no-open` — не открывать PNG автоматически (для тестов).
- `--max-nodes` — ограничить число вершин при сетевом обходе (по умолчанию 40).
- `--out` — каталог для файлов `.dot` и `.png` (по умолчанию `output`).

## Что реализовано по этапам

1. **CLI и конфигурация.** Параметры передаются через командную строку,
   отображаются в виде ключ–значение; ошибки параметров обрабатываются.
2. **Сбор данных.** Из npm Registry читаются прямые зависимости пакета
   JavaScript. Пример: `--stage 2 --package is-odd --repo https://registry.npmjs.org`.
3. **BFS без рекурсии.** Обход всех достижимых зависимостей с учётом циклов,
   возможность использовать тестовый JSON-граф с именами A–Z.
4. **Порядок загрузки.** При `--show-order` печатается порядок, в котором
   зависимости идут раньше пакета, который их требует. При цикле выводится
   предупреждение: строгий топологический порядок для цикла невозможен.
   Сравнение через `--compare-npm` вызывает штатную команду `npm view`.
5. **Graphviz и визуализация.** Создаётся DOT-файл, Graphviz генерирует PNG,
   изображение открывается на экране; `--ascii-tree` печатает дерево.

## Тесты

```powershell
python -m unittest discover -s tests -p "test_*.py" -v
.\scripts\test_all.bat
```

Тестовые графы:

- `simple.json`: A → B,C; B,C → D (общая транзитивная зависимость).
- `cycle.json`: A → B → C → A (цикл) и C → D.
- `deep.json`: цепочка A → B → C → D → E.

Тесты не требуют подключения к интернету и npm.

## Проверка трёх пакетов и сравнение с npm

```powershell
.\scripts\demo_real.bat
.\scripts\compare_npm.bat
```

Демонстрация для **is-number**, **is-odd**, **is-even** создаёт три графа.
Файлы `output/*.dot` и `output/*.png` локальные и не добавляются в Git.

`npm view is-even dependencies --json` показывает зависимости последней версии
в реестре. `npm ls --all` показывает **установленное** дерево npm и может
отличаться от нашего графа. Штатный npm разрешает диапазоны версий,
дедуплицирует пакеты, учитывает peer/optional зависимости. Наш упрощённый
анализатор берёт **последнюю версию каждой найденной библиотеки**, только
`dependencies`, и отображает граф по именам пакетов, а не по конкретным
экземплярам версий. `npm ls` показывает дерево, а не реальный временной
порядок скачивания; поэтому выводы не следует считать одинаковыми.

## Структура

- `src` — исходники программы.
- `tests` — unit-тесты и тестовые репозитории.
- `scripts` — запуск всех тестов и сравнение с npm.
- `run.bat` — быстрый запуск примера.
- `.gitignore` — исключает временные и бинарные файлы.

## Пример

```powershell
python src/main.py --stage 5 --package A --repo tests/fixtures/cycle.json --test-mode --ascii-tree --show-order --no-open
```

На экране будет обход BFS, сообщение о цикле, ASCII-дерево и путь к PNG.
